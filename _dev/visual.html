Rediseño de CSS/UX del admin (2026-09-16)

Tras varias rondas de feedback visual real, se fijó un sistema único: 6 variantes de botón con variables reales de Tabler (no colores inventados), sin bordes decorativos (solo color de fondo sólido), hover forzado con !important (WordPress core gana el empate si no se fuerza), y la tabla del Registro con el layout arreglado. Todo documentado como regla permanente en decisiones.md.

Últimas decisiones

  • Nombre: AI Knowledge & Visibility, slug ai-knowledge. Namespace de código (WOOKB) y slug de menú se mantienen sin cambiar.
  • El generador vía IA (OpenAI) + Support Genix sigue siendo el núcleo del producto; la capa de visibilidad (JSON, Markdown público, JSON-LD, etc.) se añade encima, no lo sustituye.
  • Nunca se escribe robots.txt automáticamente sin confirmación explícita del usuario.
  • Borrar llms.txt físico sí es posible desde el admin (Fase 6), pero siempre con confirmación fuerte en JS y explicando antes que el plugin genera el suyo dinámicamente al vuelo — nunca un borrado silencioso.
  • Hover/foco de elementos nativos (botones, <select>) pisados por WordPress core: se resuelve con !important, es la solución estándar del proyecto, no una excepción rara.
